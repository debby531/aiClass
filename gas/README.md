# 結帳訂單寫入 Google Sheet（GAS 設定步驟）

這個資料夾的 `Code.gs` 是一個 Google Apps Script，部署後會變成一個網址（Web App）。
網站結帳表單送出時會呼叫這個網址，自動把訂單寫進你的 Google Sheet 裡。

## 1. 建立 Google Sheet

1. 到 [Google Sheets](https://sheets.new) 新增一份空白試算表，取個名字，例如「煎好 GOOD CRISP 訂單」。
2. 不用自己建欄位，第一次收到訂單時腳本會自動建立一個叫「訂單」的工作表，並補上標題列。

## 2. 貼上 Apps Script 程式碼

1. 在這份試算表裡，點選上方選單「擴充功能 → Apps Script」。
2. 把跳出來的編輯器裡原本的範例程式碼全部刪掉，貼上 `Code.gs` 的內容。
3. （選用但建議）把 `Code.gs` 最上面的 `const SHARED_SECRET = '';` 改成你自己的一組密碼，例如：
   ```js
   const SHARED_SECRET = 'jianhao-2026-xyz';
   ```
   這組密碼待會也要貼到 `index.html` 裡的 `ORDER_SECRET`，兩邊要一模一樣。這只是用來擋掉網路上亂打請求的人，不是真正的帳號密碼機制，但聊勝於無。
4. 按儲存（磁片圖示）。

## 3. 部署成「網頁應用程式」

1. 右上角「部署 → 新增部署作業」。
2. 類型選「網頁應用程式」。
3. 「執行身分」選 **我**（你自己的帳號）。
4. 「誰可以存取」選 **所有人**（Anyone）— 這樣網站才能用匿名方式呼叫，不需要你的 Google 帳號登入。
5. 按「部署」，第一次會跳出 Google 的授權畫面，照著按「允許」即可（這是在授權你自己的腳本讀寫你自己的試算表，正常現象）。
6. 完成後會給你一個網址，長得像：
   ```
   https://script.google.com/macros/s/AKfycbx.../exec
   ```
   複製這個網址。

> 之後如果你修改了 `Code.gs` 的內容，要記得「部署 → 管理部署作業 → 編輯（鉛筆圖示）→ 版本選『新版本』→ 部署」，網址才會套用新程式碼；直接存檔不會更新已部署的網址。

## 4. 回到 index.html 填上設定

打開 `index.html`，找到這幾行（在 `<script>` 區塊裡，靠近購物車變數宣告的地方）：

```js
const ORDER_ENDPOINT = '';
const ORDER_SECRET = '';
```

改成：

```js
const ORDER_ENDPOINT = 'https://script.google.com/macros/s/你的部署ID/exec';
const ORDER_SECRET = 'jianhao-2026-xyz'; // 跟 Code.gs 裡設的要一樣
```

存檔、重新整理網頁，結帳表單的文字會自動從「示範」字樣變成正式送出訂單的文案（這是前端自動判斷 `ORDER_ENDPOINT` 有沒有填寫，不用額外調整別的地方）。

## 5. 測試

1. 在網站上加幾樣商品到購物車，走一次結帳流程送出訂單。
2. 回到 Google Sheet，應該會看到「訂單」工作表多了一列資料。
3. 如果送出後網站跳出「訂單送出失敗」的提示：
   - 先用瀏覽器直接打開 `ORDER_ENDPOINT` 那個網址，應該會看到 `{"ok":true,"message":"..."}`；如果看到登入頁或錯誤頁，回去檢查步驟 3 的「誰可以存取」是否為「所有人」。
   - 確認 `Code.gs` 和 `index.html` 的 `SHARED_SECRET` / `ORDER_SECRET` 拼字一致。
   - 改過 `Code.gs` 後記得要「部署新版本」，單純存檔不會生效。

## 關於安全性與限制

- 這個網址一旦設為「所有人可存取」，理論上任何知道網址的人都可以呼叫它寫入資料；`SHARED_SECRET` 能擋掉隨意亂打的流量，但不是嚴謹的身份驗證，請不要拿來處理真正敏感的資料（例如信用卡號——這個流程本來就沒有、也不應該收集付款資訊）。
- Apps Script 的免費額度對一般小吃店的訂單量來說綽綽有餘，但如果流量暴增（例如被惡意灌爆），可能會碰到 Google 的每日執行配額限制。
- 這個方案不處理金流／收款，純粹是把訂單內容記錄下來，取餐、付款仍依門市現場流程進行。
